# Porting a Raycast extension to Vicinae

Every item here was hit while porting the Raycast Bitwarden extension, and each
one breaks the build or the runtime in a way that is not obvious from the type
definitions.

`@vicinae/api` is a close relative of `@raycast/api`, so most code ports with a
find-and-replace. The exceptions are collected here.

Verified against `@vicinae/api` 0.29.0 and Vicinae 0.29.0.

## Package mapping

| Raycast | Vicinae |
| ------- | ------- |
| `@raycast/api` | `@vicinae/api` |
| `@raycast/utils` | **keep it** — it works, and the store's own `keepassxc` extension depends on it |
| `execa` | `node:child_process` `execFile` |
| `fast-fuzzy`, `fuse.js` | nothing — use the builtin fuzzy `List` filter |
| `@otplib/*` | `otpauth` |
| `node-stream-zip` | nothing, unless you genuinely need zip handling |

## Manifest

The manifest keeps Raycast's format, but the validator is stricter in places.

```jsonc
{
  "$schema": "https://raw.githubusercontent.com/vicinaehq/vicinae/refs/heads/main/extra/schemas/extension.json",
  "name": "my-extension",     // slug, >= 3 chars
  "title": "My Extension",    // no leading/trailing space
  "description": "At least 16 characters, no newlines.",
  "license": "MIT",           // literally only MIT is accepted
  "platforms": ["Linux"],
  "author": "black",          // ^[a-zA-Z0-9-*~][a-zA-Z0-9-*._~]*$
  "contributors": ["jomifepe"],  // array of strings
  "icon": "extension_icon.png",   // 512x512, resolved from assets/
  "commands": [
    {
      "name": "search",       // maps to src/search.tsx
      "title": "Search",
      "description": "At least 16 characters.",
      "mode": "view",         // "view" | "no-view" | "menu-bar"
      "icon": "search.png"    // optional; inherits the extension icon
    }
  ]
}
```

Preference shapes that differ from the obvious reading:

- **checkbox needs `label` *and* `title`.** `label` is the text next to the box;
  `title` groups it in the settings pane.
- `dropdown` requires `data: [{ title, value }]`.
- Command-level and extension-level `preferences` both exist; the former is
  namespaced as `Preferences.<CommandName>` in the generated types.

Run `npm run lint` after any manifest edit. It is fast and catches all of this.

## tsconfig

```jsonc
{
  "include": ["src/**/*", "test/**/*", "vicinae-env.d.ts"],
  "compilerOptions": {
    "noUncheckedIndexedAccess": true,
    "allowImportingTsExtensions": true,   // for test imports
    "baseUrl": ".",
    "paths": { "~/*": ["src/*"] }
  }
}
```

`vicinae-env.d.ts` is generated by `vici build` from the manifest and declares
the global `Preferences`, `Arguments` and `AllPreferences` types. **It must be in
`include`**, or every `getPreferenceValues<Preferences>()` fails with
"Cannot find name 'Preferences'". It is generated, so git-ignore it.

## API differences that break code

### Icons

Ten Raycast icon names do not exist in Vicinae. Map them once in a shim module
rather than editing call sites — see `bitwarden/src/utils/icons.ts`.

| Raycast | Vicinae |
| ------- | ------- |
| `Icon.Clipboard` | `Icon.CopyClipboard` |
| `Icon.Document` | `Icon.BlankDocument` |
| `Icon.ExclamationMark` | `Icon.Warning` |
| `Icon.Globe` | `Icon.Globe01` |
| `Icon.List` | `Icon.CheckList` |
| `Icon.Message` | `Icon.SpeechBubble` |
| `Icon.QuestionMark` | `Icon.QuestionMarkCircle` |
| `Icon.RaycastLogoNeg` | `Icon.Bolt` |
| `Icon.Sidebar` | `Icon.AppWindowSidebarLeft` |
| `Icon.Window` | `Icon.AppWindow` |

Export the shim as a **value and a type**, so it can be used in both positions:

```ts
export const Icon = { ...VicinaeIcon, Clipboard: VicinaeIcon.CopyClipboard } as const;
export type Icon = (typeof Icon)[keyof typeof Icon];
```

A `Proxy` does not work: TypeScript resolves the type from `typeof VicinaeIcon`
and the fallback names stay invisible.

### Shortcuts

Raycast takes a per-platform object. Vicinae takes one shortcut.

```tsx
// Raycast
shortcut={{ macOS: { key: "p", modifiers: ["opt"] }, Windows: { key: "p", modifiers: ["alt"] } }}

// Vicinae (Linux)
shortcut={{ key: "p", modifiers: ["alt"] }}
```

`cmd` maps to Control on Linux; the extensions in the store overwhelmingly use
`cmd` for the common verbs, and `alt` for the rest.

### `Toast`

Vicinae's `Toast.Options` has **no** `primaryAction` or `secondaryAction`. Raycast
code that offers "Copy Error" from a toast has to move that into the action
panel or drop it.

`Toast.Style`, `toast.title`, `toast.message`, `toast.show()`, `toast.hide()` and
`toast.update()` all behave the same.

### `Detail`

- No `isLoading` prop. Use `<Form isLoading />` or a list with `isLoading`.
- `List.Item.Detail` exists and takes `markdown` / `metadata`.

### `Clipboard`

`Clipboard.copy(value, { concealed: true })` exists and is the right way to keep
passwords out of the clipboard history — `concealed` selections are not indexed
by the clipboard manager.

`Clipboard.paste(value)` works on Wayland and X11. **Do not shell out to `wtype`,
`xdotool` or `wl-copy` for this** — that duplicates the API and is blocked by
store rule API-001.

### Window / focus

`getFrontmostApplication()` exists. Use it for "Paste into Firefox" style action
titles rather than querying Hyprland or GNOME yourself.

### Renamed functions

| Raycast | Vicinae |
| ------- | ------- |
| `showInFinder` | `showInFileBrowser` |
| `popToRoot({ clearRootSearch })` | `popToRoot({ clearSearchBar })` |
| `getSelectedText()` | present, same name |
| `popToRootType` | `PopToRootType`, same name |

### LocalStorage and Cache

`LocalStorage` only accepts `string | number | boolean`. Serialize objects with
`JSON.stringify`.

`Cache` exists with the same surface, but note that `Cache.isEmpty` is a
**getter**. `if (!Cache.isEmpty)` is correct; `if (!Cache.isEmpty())` is not.

### `useNavigation`

`push` and `pop` exist but are typed `any`. Pushing a React element works.

### Types not exported

`Action.Props` and `List.EmptyView.Props` do not exist as type members. Use:

```tsx
type ActionProps = React.ComponentProps<typeof Action>;
type EmptyViewProps = React.ComponentProps<typeof List.EmptyView>;
```

`KeyEquivalent` is a top-level exported type, not a member of the `Keyboard`
namespace:

```ts
import type { KeyEquivalent } from "@vicinae/api";
```

`EmptyViewProps` is not exported from the package root, so do not reach into
`@vicinae/api/dist/...` — that path changes between releases.

## `@raycast/utils` interop

The package works at runtime — verified by launching a built extension that
imports it and finding `Loaded extension` / `Started extension` in
`vicinae.log` with no module-resolution error, even though the bundle contains
an external `require("@raycast/api")` and the installed extension directory has
no `node_modules`. The store's `keepassxc` extension ships the same way.

Its types, however, reference `@raycast/api`'s `Form`, which is not structurally
identical to Vicinae's. The symptom is:

```
Type '(values: MyForm) => void' is not assignable to type '(input: Values) => ...'
```

Bridge it in one helper rather than casting at each call site — see
`bitwarden/src/utils/form.ts`:

```ts
export function asSubmitHandler(
  handleSubmit: unknown,
): (values: Form.Values) => Promise<boolean | void> {
  return (values) => (handleSubmit as (v: unknown) => unknown)(values) as Promise<boolean | void>;
}
```

For forms that re-render on every keystroke, skip `useForm` entirely and use
plain `useState`; it is less code and needs no cast.

## Replacing the search library

Vicinae fuzzy-filters `List` items in C++ by default. Passing `onSearchTextChange`
disables it, so to use the builtin filter, do not pass that prop, and feed the
extra search terms through `keywords`:

```tsx
<List.Item title={item.name} keywords={getSearchKeywords(item)} />
```

Keywords rank below the title, which is the behaviour you want. Items inside
`List.Section` are still filtered.

## Platform-specific Raycast code to delete

- `platform === "darwin"` / `"windows"` branches, and `src/utils/platform.ts`
  entirely for a Linux-only extension.
- macOS system-log queries (`log show --predicate ...`) for screen-lock and sleep
  detection. On Linux, ask systemd-logind instead:
  `loginctl show-session "$XDG_SESSION_ID" -p LockedHint --value` returns `yes`
  when the session is locked. If logind is absent, fail open — failing closed
  would lock the user out on every launch.
- `homebrew`, `sw_vers`, PowerShell and Chocolatey probes.
- macOS SF Symbols in `assets/` (`sf_symbols_*.svg`); use a built-in `Icon`.
- Per-platform `default` blocks in preferences.

## Downloading a bundled binary

The Raycast Bitwarden extension downloads a ~100 MB platform binary. Do not port
that pattern: on Linux the tool is a distro package. Resolve the binary from a
preference or `PATH`, and surface a clear installation hint if it is missing.

## Security notes

- Pass secrets through the environment, never `argv`. `bw unlock --passwordenv
  BW_PASSWORD` rather than `--password`. Anything in `argv` is world-readable in
  `/proc`.
- Use `concealed: true` when copying secrets.
- Redact a master password from any error text before it reaches a toast or a
  log. Escape regex metacharacters when doing so.
- Do not log vault contents.
